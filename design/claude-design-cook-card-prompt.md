Design the **Cook card page** (page 8 — what you get after Live cook, and can reopen from Home's "Recent runs") using the **Kitchen Path Agent Design System v1.0** already on this canvas. Everything visual — color tokens, Scale A type, 4px spacing, radii, the 14-glyph icon sheet, motion tokens, game vocabulary, the goose PlayerAvatars and the component set — comes from that system. Do not introduce any color, font, radius, shadow or icon it doesn't define. This brief describes **what the page must do and which data it has**; where it proposes something the backend doesn't store yet, it says so explicitly (§6) so the result can still be wired to what exists today.

The Cook card is the run's **trophy shelf**: the one page a player comes back to, screenshots, and sends to the other player. It is *not* a play surface (no timers, no actions on steps) and *not* a planning surface (no editing). It sits between the two: white and calm like Home, but it keeps the player colors, the geese, large mono numbers and one **frozen** celebration state — the record of a specific evening, never changing after the fact.

The player's job here, in order: **1) see the result, 2) put the food on the card, 3) keep or send it, 4) cook again.**

**Deliver:** Desktop 1280 and Mobile 390 artboards of the main state (**A · Versus, photo added**), a strip of the other states (B–G below), and the **share card artboard at 1080 × 1350** (4:5, the exported PNG) in both a Co-op and a Versus version.

## 2. Data the page receives (already fetched; nothing else exists)

```
summary       { createdAt:ISO, dish, mode:"cooperation"|"competition",
                totalSec, estimatedSec:number|null,          // estimatedSec is null for Versus
                winnerCookIds[]: cookId,                     // 0, 1 or 2 ids (2 = tie)
                headline: string,                            // engine-written, e.g. "Mia ran away with it by 35 points."
                cooks[] (sorted by points desc): {
                  cookId, name, colorKey, points, rank, isWinner, doneCount, skippedCount,
                  quips[]: string (0–2),                     // engine-written, e.g. `"Blanch tofu" took 3 min longer than anyone promised.`
                  steps[]: { label, status:"done"|"skipped", estSec, actualSec, deltaSec, points } },
                photo: dataUrl|null, styledPhoto: dataUrl|null, photoSource: "model"|"stub"|null }

session       { id, kitchenProfileId, recipes[]: { working:{ title, servings } } }   // for kitchen name + servings
kitchenProfiles[]  { id, name }
history[]     every finished run: { id, dish, totalSec, mode, endedAt, hasCard }       // Home already has this
```

Values you may derive and show:

- **Title** = `dish`. **Date** = `createdAt` → "Sep 16". **Meta** = "{Co-op | Versus} · {kitchen name} · {servings} servings".
- **Time on the clock** = `totalSec` mono; under a minute show "48s", otherwise "38:20". **Plan delta** (Co-op only, `estimatedSec` non-null) = |totalSec − estimatedSec| → "3:10 over plan" (`--kp-warning-text`) or "2:00 inside the plan" (`--kp-status-done`).
- **Winner** (Versus): `winnerCookIds` → one Winner chip with the `trophy` glyph; two ids → "Tied" chip on both, no trophy. Co-op: **no winner, no points, no rank anywhere** — see §5.
- **Steps** = Σ doneCount; **skipped** = Σ skippedCount. **Longest step** = the done step with the largest `actualSec`; **biggest overrun** = largest positive `deltaSec` (label + mono delta).
- **Plan vs actual bar** per step: two thin bars, planned (`estSec`, `--kp-border`) and actual (`actualSec`, player color; the part beyond planned in `--kp-warning`). Derivable from `steps[]` alone.
- **Personal best** (derivable from `history[]`, no backend change): among finished runs with the same `dish` and `mode`, is this `totalSec` the smallest? → **"New best"** chip with `trophy`, accent. Otherwise, if a faster one exists: meta "Best: {mono} on {date}". Only when there are ≥ 2 comparable runs.
- **Hero image** = `styledPhoto || photo`. Say "Styled by the agent" **only** when `photoSource === "model"`; for `"stub"` say nothing at all — a local filter is not a feature, and "no image model wired up yet" is a dev note, not player copy.

## 3. Page structure (top → bottom), mapped to system components

1. **Header**: eyebrow (13/400, text-secondary) "{date} · {Co-op | Versus}", title = dish (30/700), meta line (kitchen · servings). Right side on desktop: the **HUD** — mono **{time on the clock}** 32/500 with the `timer` glyph, and the plan-delta chip (Co-op) or the Winner chip (Versus).

2. **Headline** — the engine's `headline`, set as the page's one big line: 22/500, `--kp-ai` (it's the agent speaking), with the agent goose 24 leading it. This is the emotional hook; give it air (24px above and below). Never truncate.

3. **Photo hero** — list-card with zero padding, 16:10 on desktop, 4:3 on mobile, radius from the system.
   - **Empty**: a dropzone in bg-secondary with the `oven`-family glyph? No — the sheet has no camera; use **text only**: "Add a photo of the food" (18/700) + "It goes on the card." (13/400) + primary **Button lg "Add a photo"**. Mobile opens the camera directly (`capture=environment`).
   - **Busy**: same block with the pulsing mono "…" and the meta "Reading photo…" / "Styling…".
   - **Filled**: the image, cover-fit; a translucent bottom bar (the system's overlay treatment, if any; else a plain bg-secondary foot below the image) with ghost "Swap photo" and, only when `photoSource === "model"`, the meta "Styled by the agent" with the agent goose 16.
   - Failure: Error tint line under the card "{message}"; the previous photo (if any) stays.

4. **Result block** — mode-specific, on bg-secondary.
   - **Versus → Scoreboard.** Two **PlayerResultCards** side by side (player color treatment as the system defines for result/summary; the winner's card additionally carries the Winner chip with `trophy`, spring pop on first paint). Each: PlayerAvatar 48 + name 18/700; mono **points 40/500** in the player color (ScoreCounter roll-up once); meta "{done} done · {skipped} skipped"; then the player's `quips` (0–2 lines, 15/400, text-primary, each on its own line, quote-styled with a 2px rail in the player color). Tie: both cards get a neutral "Tied" chip, neither gets the trophy.
   - **Co-op → Team result.** One card, both PlayerAvatars overlapping (32) + "Together"; three stat tiles: **{time}** "on the clock" · **{planned}** "planned" · **{steps}** "steps" (mono 24/500, labels 13/400); the plan-delta line under them in its status color. Then each player's `quips` as two short columns with PlayerAvatar 24 + name — quips are still per player, points are not shown.
   - **Personal best**: the "New best" chip sits on this block's header row when earned; otherwise the "Best: …" meta on the right.

5. **Who did what** — list-card, two columns (one per player, header = PlayerAvatar 24 + name + mono "{n} steps"). One **ListRow** per step in `steps[]` order: title = label (15/500), trailing mono "{actual}" and, when `deltaSec > 0`, " · +{delta}" in `--kp-warning-text`; Versus adds " · +{points}" in the player color. Under each row the thin **plan vs actual bar** from §2 (planned in border grey, actual in the player color, overrun in warning). Skipped rows: text-tertiary, strikethrough label, trailing "skipped", no bar. Empty column: "Nothing completed." (text-tertiary).
   - Header meta on the right of the card title: "Longest: {label} {mono}" and, when any overrun ≥ 60 s, "Biggest overrun: {label} +{mono}".

6. **Footer band**: left = secondary **"Save the card"** (busy: "Building card…") and secondary **"Copy link"** (2 s success swap to "Link copied" with `checkmark-burst` 16); right = primary **Button lg "Cook this again →"** (§6, needs a small backend hook — falls back to ghost "Home" if not wired) and ghost **"Home"**.

Desktop 1280: header + HUD one row; headline; photo hero full width (max height 480); result block; Who did what two columns; footer. Mobile 390: everything stacks; the HUD becomes a row of two chips under the title; scoreboard cards stack; Who did what becomes one column with a two-segment player toggle at the top; footer primary full-width, secondaries in one row below it.

- Top 60 %: the hero photo, cover-fit. No photo → the page ground with the system's kitchen-counter line-drawing banner (from Home v3) at reduced opacity; never a grey box.
- Below: "KITCHEN PATH" mono 13 letterspaced (text-tertiary) with the `fork-branch` mark; dish 44/700 (wraps to 2 lines max); meta "{Co-op | Versus} · {date} · {mono time}"; the **headline** 26/500 in `--kp-ai`.
- Then one row per player: PlayerAvatar (goose, 64) + name 32/700 + right-aligned mono 40/500 — **points** in Versus, **"{n} steps"** in Co-op — with the Winner `trophy` next to the winner's name (Versus).
- Bottom-right corner: a small "New best" chip when earned.
- Safe margins 64px; nothing else. No QR, no URL — the app has no public share host yet.
- Provide it in Co-op and Versus variants, with and without photo.

## 5. States

**A. Versus, photo added — the main state.** Mia 65 · Leo 45, Winner chip on Mia, headline "Mia took it by 20. Closer than the scoreline suggests.", one quip each, Who did what with a few +deltas. Design this one first.

**D. New best.** As A with the "New best" chip on the result block and on the share card.

**E. Photo busy / photo failed.** The hero in its Busy state; the same hero with an Error line "That doesn't look like an image".

**F. Card not found.** Title "No card for this cook", meta "That cook doesn't exist any more." *or* "This run was left before anyone finished cooking, so there's no card." + primary "Home". (Reached by a stale link or from an abandoned run.)

**G. Loading.** Nothing renders until the run arrives (a blank page beats a flash of the not-found state on a hard refresh). Optional: the pulsing mono "…".

## 6. Proposed additions — clearly marked, so nothing is wired that doesn't exist

The page's data is a frozen JSON blob (`summary`) that the page can PATCH back (it already does so for the photo). Adding a field to it is cheap; anything else is a real backend change. Design these, tag each with its cost:

1. **"Cook this again →"** — *needs one small hook*: start a new run in the same kitchen with the conversation pre-filled from this session's answers, landing on Inventory. Primary CTA in the footer. Until it exists, the footer primary is "Home".
2. **One-line note** — *summary field only* (`summary.note`, string ≤ 140): a single text field under the result block, placeholder "One thing to remember next time…", saved on blur with a quiet "Saved" meta. This is the seed of the future "diary" stage without building it. Shown on the share card as an italic line under the headline when present.
3. **Personal best** — *no backend change*, computed from `history[]` (§2). Include it.
4. **Plan vs actual bars** — *no backend change*, from `steps[]`. Include them.
5. **Send to the other player** — *no backend*: on mobile use the native share sheet with the PNG (Web Share API) as the "Save the card" fallback; annotate as "share sheet where available, download elsewhere".
6. **Not included, on purpose**: star ratings, comments, reactions, public feed — nothing stores them, and one note beats five widgets nobody fills in.

## 7. Rules

- Copy in this brief is final; engine-written headline/quips are verbatim. English-only.
- Mono (JetBrains Mono) for every number: the clock, points, deltas, step counts, dates in chips, the share card figures.
- Icons only from the 14-glyph sheet: `timer`, `trophy`, `checkmark-burst`, `fork-branch`; the geese for avatars (agent goose for the headline). No camera icon exists — the photo affordance is text + button. No emoji, no other icon set.
- Player colors appear only on: PlayerResultCards / bundle rails, points figures, quip rails, plan-vs-actual actual bars, share-card rows. `--kp-ai` is reserved for the engine's headline. `--kp-warning-*` for overruns and "over plan". `--kp-status-done` for "inside the plan" and the copied-link confirmation. `--kp-critical` never appears on this page.
- Co-op never shows points, rank or a winner. Versus never shows the plan delta (there is no plan).
- Mobile 390: single column, 16px gutters, 44px targets, primary full-width, no horizontal scrolling. The photo dropzone opens the camera.
- prefers-reduced-motion: per the system, every motion becomes a 200 ms fade; the ScoreCounter and the Winner chip render their final state immediately.
